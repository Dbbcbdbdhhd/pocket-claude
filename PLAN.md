# План развития Pocket Claude

Статус: **подтверждён 2026-10-22**, идёт этап 1. Документ живой: после каждого этапа здесь отмечается, что сделано и что дальше.

## Как работаем

1. Один этап = одна ветка и один PR в `main`. Внутри этапа каждое законченное изменение — отдельный commit + push, чтобы прогресс был виден на GitHub.
2. В конце этапа я пишу отчёт: что сделано, как проверено, что не удалось проверить (Windows и iPhone здесь недоступны — такие вещи проверяешь ты по чек-листу), что делаем следующим.
3. Ты подтверждаешь («ок, дальше» или правки) — я начинаю следующий этап.
4. Порядок этапов можно менять: после подтверждения плана скажи, с чего начать.

Размер: **S** — до дня, **M** — несколько дней, **L** — неделя+, **XL** — несколько недель.

## Что есть сейчас

- **brain** (Mac) запускает Claude Code через Agent SDK, держит сессии, раздаёт разрешения, пересылает вызовы инструментов на компьютеры.
- **relay** (Cloudflare Worker или Node на Mac за Tailscale) видит только шифротекст, умеет офлайн-очереди для телефонов.
- **client** — Android-приложение (Expo, маскировка под соцсеть, чат с «Lipton» в Direct) и панель VS Code.
- **executor** — расширение VS Code (инструменты в workspace) и `PocketClipboard.exe` на Windows (только буфер обмена).
- Один brain = один владелец: все устройства равноправны, разделения по людям нет (`daemon.ts` → `toClients()` шлёт события всем клиентам).
- С телефона уже есть «To PC»: текст/код из ответа кладётся в буфер Windows (`clipboard.set` → `clipboard.write` → PowerShell).

## Цели

1. **Windows-оверлей**: двойное нажатие Alt показывает/прячет небольшое окно справа, куда транслируются ответы ИИ. Только чтение, с кнопками «Копировать».
2. **Несколько людей и компьютеров**: регистрация в приложении, у каждого свои телефон, компьютеры и чаты.
3. **Telegram-бот**: меню с функциями буфера обмена (забрать текст/картинку/скриншот с Windows, положить текст/фото в буфер), выбор компьютера; опционально — чат с Claude.
4. **Mini App**: то же приложение внутри Telegram.
5. **iPhone**: приложение как на Android, с Face ID.

## Решения по архитектуре

### 1. Windows-оверлей

**Где живёт.** Внутри `PocketClipboard.exe` (`apps/clipboard-agent`): новых установщиков не появляется, агент уже стоит в автозагрузке и уже спарен с Mac.

**Откуда берёт ответы.** Агент объявляет новую capability `overlay` (сейчас — `['clipboard']`). Brain рассылает таким устройствам события сессий: текст ответа (стриминг через `text_delta`, как телефону), реплики пользователя, смену состояния, завершение. Вызовы инструментов — одной строкой, запросы разрешений — не показываем (их решают с телефона). При подключении агент получает список сессий и историю последней. Изменения в brain: `toClients()` получает «зеркальную» рассылку на executor'ы с `overlay`; `session.list`/`session.history` разрешаются таким executor'ам (сейчас executor-ветка `onMessage` принимает только `tool.*`/`clipboard.*`/`executor.status`).

**Окно.** PowerShell 5.1 + WinForms, тем же способом, каким агент уже работает с буфером (`-STA`, `Add-Type`). Узел общается с процессом окна по stdin/stdout строками JSON. Окно: без рамки, поверх всех, **не в панели задач**, скрыто по умолчанию, прижато к правому краю рабочей области (~420 px), тёмная тема, не забирает фокус при показе. Содержимое: заголовок чата, реплики пользователя (приглушённо), ответы ИИ; код — моноширинным блоком с кнопкой «Копировать»; у ответа — «Копировать ответ»; выделение + Ctrl+C работают нативно. Markdown разбираем тем же парсером, что панель VS Code (`panel/webview/format.ts` → вынести в `client-core`).

**Двойной Alt.** Опрос `GetAsyncKeyState(VK_MENU)` раз в ~25 мс: два коротких нажатия (<250 мс каждое) в пределах 400 мс. Без низкоуровневого хука клавиатуры — он выглядит как кейлоггер для антивирусов. Esc прячет окно. Если понадобится точнее (например, отличать Alt+Tab) — перейдём на `WH_KEYBOARD_LL`.

**Содержимое (подтверждено):** и свои сообщения (приглушённо, для контекста), и ответы ИИ.

**Управление.** `PocketClipboard.exe overlay on|off` (по умолчанию включён на Windows; хранится в state агента). Позже — переключатель на телефоне в карточке компьютера («Показывать ответы на ПК»).

**Ограничение.** В этой среде нет Windows: логика (состояние сессий, протокол окна, парсер) покрывается тестами в Node, а сам WinForms-скрипт проверяешь ты по чек-листу.

**Альтернатива, которую не берём:** окно браузера Edge в режиме `--app` (красивее рендер, но видно в панели задач, тяжёлый процесс). WebView2 внутри WinForms — возможный апгрейд рендера позже (нужно тащить DLL SDK рядом с exe).

### 2. Несколько людей и компьютеров

**Модель.** Один Mac/brain обслуживает нескольких **пользователей**. Пользователь = запись в `BrainState.users` (id, имя, дата, позже — Telegram ID). Каждое спаренное устройство (`PairedDevice`) получает `userId`. Существующие устройства при миграции попадают владельцу Mac.

**Регистрация.** Приглашение создаёт владелец: из CLI (`pocket-claude invite "Маша"` → QR + ссылка) или с телефона (Настройки → «Пригласить человека»). Новый человек открывает приложение, сканирует QR/вставляет код — это и есть регистрация: экран пейринга получает поле «Как тебя зовут?», имя уходит в `PairRequest` (поле `userName`), brain создаёт пользователя и привязывает к нему телефон. Дальше «Добавить компьютер» на телефоне (`computer.pair`) выдаёт код, помеченный этим пользователем, — его компьютеры (VS Code, PocketClipboard) привязываются к нему автоматически.

**Разделение.** Чаты, компьютеры, буфер обмена, запросы разрешений, оверлей — только внутри своего пользователя: `toClients()` → `toClientsOf(userId)`, `session.list`/`computers`/`clipboard.*`/`computer.select` фильтруются по владельцу. Mac как исполнитель (файлы самого Mac) доступен только владельцу. Лимит одновременно живых сессий (`MAC_LIVE_SESSIONS = 2`) остаётся общим для Mac — это ресурс машины; при необходимости сделаем настраиваемым.

**Администрирование.** CLI: `pocket-claude users` (список), `pocket-claude users remove <id>` (удаляет пользователя и все его устройства). Relay менять не нужно: роли и ростер остаются прежними, разделение живёт в brain.

**Claude-аккаунт один** — все пользователи работают через подписку владельца Mac; расход виден в `usage` по сессиям.

### 3. Telegram-бот

**Где живёт.** Новое приложение `apps/telegram-bot`, запускается на Mac как LaunchAgent `com.pocketclaude.telegram` (long polling → публичный адрес не нужен). Токен бота от @BotFather хранится в state на Mac (`pocket-claude telegram <token>`), в git не попадает. Библиотека — grammY (TypeScript, без тяжёлых зависимостей).

**Привязка.** Для каждого Telegram-пользователя бот — отдельное клиентское устройство (как ещё один телефон). На телефоне: Direct → ☎ → «Telegram» → выдаётся код пейринга в виде ссылки `t.me/<бот>?start=<код>`. Человек нажимает её, бот получает `/start <код>`, делает `joinAccount(role: 'client', name: 'Telegram @username')`, сохраняет личность у себя и поднимает `ChatClient` из `client-core`. Так многопользовательность из этапа 2 работает для бота сама собой, а владелец видит и может удалить «Telegram @username» как обычное устройство.

**Меню (reply-клавиатура).**

| Кнопка | Что делает |
|---|---|
| 📋 Буфер → сюда | `readClipboard(ПК)`: текст — сообщением (длиннее 4096 — файлом .txt), картинка/скриншот — фото, файлы — документами (лимит агента 20 МБ) |
| 📥 Текст → в буфер | следующий текст (и вообще любой текст без команды) кладётся в буфер ПК |
| 🖼 Фото → в буфер | фото, присланное боту, скачивается через Bot API и кладётся в буфер как изображение (агент уже умеет `SetImage`) |
| 🖥 Компьютер | выбор целевого ПК из своих (inline-кнопки), показывает кто онлайн |
| ℹ️ Статус | Mac/Claude/ПК онлайн, кто привязан |
| /unlink | отвязать Telegram |

**Скриншоты.** Win+Shift+S кладёт в буфер bitmap; агент читает картинки из буфера (`GetImage`, сжатие до 2560 px / JPEG при >3 МБ) — «Буфер → сюда» пришлёт скриншот как фото. Проверить на Windows при приёмке.

**Файлы в буфер.** Агент сейчас принимает на запись только текст и картинки. Документы из Telegram → буфер: отдельный подэтап (сохранять в «Загрузки» и класть в буфер как file drop).

**Чат с Claude из Telegram** (этап 4, подтверждён): `/new`, текст → `send()`, ответ стримится правкой сообщения (`editMessageText`, не чаще 1/с, разбиение по 4096), код в ```-блоках, разрешения — inline-кнопками (Разрешить / На сессию / Запретить), `/chats` — список сессий.

### 4. Mini App

Мобильное приложение уже собирается под web (`react-native-web`, `platforms: ["android","web"]`, в `storage.ts` есть web-ветка), но только как dev-превью. Mini App = web-сборка + слой адаптеров под Telegram:

- хранилище: SecureStore → `localStorage` (v1) или `Telegram.WebApp.CloudStorage`;
- блокировка: `expo-local-authentication` → `Telegram.WebApp.BiometricManager`, где поддерживается, иначе без блокировки;
- QR-сканер: камера → `showScanQrPopup`;
- хаптика, тема, `expand()`, safe area из `contentSafeAreaInset`;
- вход по deep link `t.me/<бот>/<app>?startapp=<код>` — код пейринга прилетает в приложение и пейринг проходит сам.

**Хостинг (подтверждено: всё с Mac).** Статика раздаётся Node-relay на Mac — тот же HTTPS-адрес Tailscale Funnel, что уже используется для relay, новых сервисов не нужно. Кнопка меню бота (`setChatMenuButton`) открывает приложение.

**Риски:** Reanimated 4/expo-video в web-сборке, особенности WebView Telegram на iOS (высота, клавиатура). Проверяем на реальных клиентах Telegram (Android, iOS, Desktop).

### 5. iPhone

Есть два пути. **Выбран путь А (Expo).**

**А. Expo iOS.** Приложение уже кроссплатформенное: добавить `ios` в `platforms`, `bundleIdentifier`, иконки, тексты разрешений (Face ID уже описан в плагине `expo-local-authentication`, `faceIDPermission`), проверить экраны на iPhone (safe area, клавиатура, `KeyboardAvoidingView` уже учитывает iOS). Ключи — в Keychain через `expo-secure-store`, Face ID — через `expo-local-authentication` без изменений кода блокировки. Сборка на твоём Mac: `npx expo run:ios --device` (бесплатный Apple ID — переподпись раз в 7 дней) или Apple Developer ($99/год) → TestFlight. Один код для Android, iPhone и Mini App. Размер: **M**.

**Б. Нативно на Swift.** Полный второй клиент: протокол (Ed25519/X25519/HKDF есть в CryptoKit, **XChaCha20-Poly1305 — нет**, нужен libsodium или смена AEAD во всём протоколе), транспорт, стейт, весь UI на SwiftUI. Две кодовые базы придётся держать синхронно при каждом изменении протокола и экранов. Размер: **XL** (4–8 недель). Оправдан, только если нужны вещи, недоступные из Expo (Share Extension, виджеты) — их тоже можно добавить к Expo-приложению как нативные модули.

Маскировка под соцсеть — риск для публикации в App Store (правило 4.1). Для личного использования через Xcode/TestFlight — не проблема.

## Решения (подтверждены 2026-10-22)

1. **Порядок этапов:** оверлей → пользователи → бот (буфер) → бот (чат) → Mini App → iPhone. Этап 2 раньше бота, потому что бот и Mini App опираются на разделение по людям.
2. **iPhone:** путь А, Expo — тот же код, Face ID из коробки.
3. **Оверлей:** и свои сообщения (приглушённо), и ответы ИИ.
4. **Бот:** чат с Claude из Telegram нужен (этап 4).
5. **Mini App и всё остальное:** хостится с Mac (Tailscale Funnel), без сторонних сервисов.

## Замечания по текущему коду

- `apps/executor-extension/package.json`: дефолтный `pocketClaude.relayUrl` — личный адрес Tailscale. Для чужих установок стоит оставить пустым и спрашивать при пейринге.
- Нет корневого README и CI — добавим в 1.0.
- Push-уведомления: relay умеет хранить FCM-токены, но приложение их не регистрирует — на iOS это ничего не ломает.
